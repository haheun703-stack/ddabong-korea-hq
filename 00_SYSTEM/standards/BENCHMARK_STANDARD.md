## 1. 언제
에피소드 착수(RESEARCH 게이트) 때 **1건 이상**. 같은 주제·같은 시청층의 상위 영상 1편을 골라 뜯는다. 사용자가 고른 영상이 우선.

## 2. 파일
`09_ANALYTICS/benchmarks/BENCHMARK_<CHANNEL>_<TOPIC>_<YYYYMMDD>.md`. 영상 원본은 저장하지 않는다 (RED). 캡처는 구조 연구용으로만 로컬 보관, git 제외.

## 3. 템플릿 (기존 벤치마크 구조 그대로)
1. 기본 정보: 채널 · 구독 · 조회 · 길이 · 게시일 · 시청층 추정
2. **화면 구성 비율표** (실사 / AI / 도해 / 유물 / 자막 카드 — 초 단위 %)
3. **이야기 구조** (우리 7단계에 대입: ①~⑦ 어디에 무엇이 있나, 빈 단계)
4. 훅: 첫 3초 · 첫 30초 · 제목 · 썸네일 문구 · 각도(SCALE/MYSTERY/CONTRAST)
5. 숫자·치수 화면 표시 방식
6. **가져올 것 / 버릴 것** (각 3개 이내, 근거 한 줄)
7. 우리 계획과 비교표 → 시사점 → `DECISIONS.md` 제안(P-번호) 또는 표준 개정 후보

## 4. 규칙
- 벤치마크는 **구조**를 배우는 것이다. 문구·구도·이미지를 베끼지 않는다 (권리 RED, D-041 과 같은 원칙).
- 시사점은 사례 1개로 표준을 바꾸지 않는다. 3건 누적 또는 사용자 D-번호로만 반영.

## 5. 담당
