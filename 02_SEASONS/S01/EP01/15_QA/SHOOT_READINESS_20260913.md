## 2. H07 매치컷: 현장에서 꼭 찍고 기록할 것

### 확인됨: 이미 정해진 값 (H07 쪽)

- 렌즈 **35mm**, 카메라 높이 **1.6 m**, `static`, tilt **0 → 0**, 5초, **24fps** (`EP01/10_BLENDER/camera_CAMERA_EP01_S08_SH002_V01.json:4-17`)
- 구도 문장: "mound fills the frame in a simple wide composition … mound centred slightly off-axis … no people near camera, neutral daylight; … hard-cut to the same-shaped green mound" (`EP01/11_AI_STILLS/prompt_PRM_EP01_S08_SH002_V01.json:13`)
- 두 샷 모두 반드시 지킬 요소: `mound_silhouette` · `frame_position` · `horizon_height` (`shot_EP01_S08_SH002.json:20-24`, `shot_EP01_S08_SH003.json:20-24`)
- 착지 봉분 = 천마총 (D-026 #2, `DECISIONS.md:128`). 크기 기준은 지름 47 m, 높이 12.7 m (`LOC/LOC_CHEONMACHONG_V01.json:12-13`)
- H07에는 줌을 쓰지 않는다. 실사 구도에서 정확히 끝나야 한다 (`EP01/15_QA/AI_SHOT_PLAN_EP01.md:46`)
- 편집은 하드컷 또는 4–6프레임 짧은 디졸브이고, `match_cut_frame`을 기록하기 전에는 H07을 생성하지 않는다 (`EP01/14_EDIT/GRAPHICS_SPEC_EP01_V2.md:198-202`)
- 기록할 칸은 이미 만들어져 있다: `LOC_CHEONMACHONG_V01.json:39-58` (`status: TO_RECORD_AFTER_SHOOT`, 값 13개 모두 `null`). 칸 이름은 계획 `SHOOT_PLAN:77-87`과 같다.

**현장 기록표** (계획 §3a를 정리했다. 모두 `match_cut_frame`에 들어간다)

| 항목 | 목표 / 기록 방법 |
|---|---|
| 렌즈 | 35mm (크롭 센서면 실제 mm와 35mm 환산값을 둘 다 기록). 줌 링은 테이프로 고정 |
| 카메라 높이 | 렌즈 중심 1.6 m, 줄자로 잰다 |
| 기울기 | tilt 0, 수평계 사용 |
| 움직임 | 삼각대 고정, 20초 이상, 가까이에 사람 없음 (`SHOOT_PLAN:66-69`) |
| 봉분 위치 | 중앙에서 **약간** 벗어나게. 꼭대기와 좌우 끝이 화면 몇 %에 오는지 기록 (`mound_offset`) |
| 지평선 높이 | 화면 아래에서 몇 %인지 기록 (`horizon_height`) |
| 방향·위치 | 나침반 방위각, GPS, 삼각대 자리 사진 |
| 빛 | 한낮의 중간 톤 (H07이 "neutral daylight"). 골든아워는 피한다 (`SHOOT_PLAN:70`) |
| 잔디 색 | 초록이어야 한다 (`SHOOT_PLAN:71`). 실제 색을 `grass_colour`에 기록 |
| 날짜·해 방향·날씨·선택 클립 | `shot_datetime` · `sun_direction` · `weather` · `take_id` |

### 문제: 현장에서 그대로 따라 찍기에는 부족한 점

1. **`match_cut_frame` 칸은 촬영 후 기록용이다. 촬영 목표는 반쯤만 정해져 있다.**
   - "약간 벗어나게"가 좌/우 어느 쪽인지, 몇 %인지 정해지지 않았다.
   - 지평선 목표 높이와 봉분이 화면 폭에서 차지할 비율도 정해지지 않았다.
   - H07 문장 안에서도 "fills the frame"와 "simple wide composition"이 함께 쓰여 모호하다 (`prompt_PRM_EP01_S08_SH002_V01.json:13`).
   - 규칙상 "실사가 먼저, AI가 따라간다"라서 현장 결정으로 두어도 되긴 한다. 그래도 **여러 변형을 찍고 하나를 고르는 방식이 필요하고, 계획에 이미 있다** (`SHOOT_PLAN:33`: 3테이크 + 변형 2개).
2. **카메라와 봉분 사이 거리가 어디에도 없다.**
   - 참고 계산 (**제안**, 저장소 값 아님): 풀프레임 35mm의 가로 화각은 약 54°다. 지름 47 m 봉분이 화면 폭의 약 70%를 차지하려면 **약 60–70 m 떨어져야** 한다.
   - 천마총 주변에 그 거리를 둔 관람로가 있는지는 **현장 확인 필요**다 (`SHOOT_PLAN:132`도 같은 질문).
3. **잔디 색 조건은 D-026 본문에는 없다.** 이 조건은 H07 문장의 "green mound"에서 계획이 끌어낸 것이다 (`DECISIONS.md:126-133`에 잔디 언급 없음, `SHOOT_PLAN:71`). 촬영 날짜가 정해지지 않았으므로, 잔디가 누렇게 변할 수 있는 시기라면 **H07 문장을 고칠지 먼저 정해야 한다**.
4. **화면 비율·해상도가 기록 항목에 없다.** `take_id` 칸에만 "해상도·fps"가 있다 (`SHOOT_PLAN:87`). H07에는 줌을 쓰지 않으므로 실사 쪽에서 크롭하면 지평선 높이가 바뀐다. **4K 16:9로 찍고, 편집 크롭 없이 쓸 구도로 찍는다** (제안).
5. 참고 (촬영을 막지는 않음): H07 문장 V01에는 아직 라벨 문자열 "AI Visual Reconstruction"이 들어 있고, 장소 lock이 "under construction"이다 (`prompt_PRM_EP01_S08_SH002_V01.json:13,49`). 생성 전에 V02로 고친다는 원칙이 이미 있다 (`AI_SHOT_PLAN_EP01.md:50,53`). 실사를 찍은 뒤 기록값을 반영해 V02를 만들면 된다.

**판단: 지금 데이터로 촬영은 가능하다.** 렌즈·높이·기울기·빛·사람 없음은 정해져 있다. 봉분 위치와 지평선은 현장에서 고르고 정확히 기록하는 방식이라 **기록을 빠뜨리면 H07을 만들 수 없다.** 현장 기록표를 인쇄해서 가져가야 한다.

## 3. 권리

### 확인됨

- 자체 촬영은 증빙을 남기면 GREEN이다 (D-026 #3 `DECISIONS.md:129`, `00_SYSTEM/standards/RIGHTS_STANDARD.md:25`). 증빙 문구는 "self-shot / original footage / source file retained"다.
- 계획은 이 규칙과 옛 BLUE 표기를 쓰지 않는다는 점을 바르게 적었다 (`SHOOT_PLAN:162`).
- 사람 규칙(모르는 사람, 특히 어린이를 주인공으로 쓰지 않음, 가까운 컷은 동행자나 동의)도 있다 (`SHOOT_PLAN:163-164`, legacy `episodes/ep01-field-shoot-plan.md:117-120`).
- 실사를 확보하면 백업 이미지 3개(경주시·위키 대릉원·위키 천마총 입구)는 쓰지 않는다. 셋 다 YELLOW BACKUP_ONLY다 (`05_HISTORY_DATABASE/rights/RTS_WIKI_CHEONMACHONG_ENTRANCE_001.json:15,19` 등, `P4_ROUTER_REPORT.md:82`).

### 문제

1. **REAL 10샷 모두 `rights_ids: []`이고, 권리 기록을 언제 어떤 이름으로 만들지 정해지지 않았다.** (예: `shot_EP01_S08_SH003.json:32`, 나머지 9개도 같은 칸이 비어 있다.) 계획은 "모든 클립에 권리 기록"이라고만 적었다 (`SHOOT_PLAN:160`).
2. **검증기가 이 빈칸을 잡지 못한다.** `validate.py`는 ARCHIVE 샷에만 rights_ids를 강제한다 (`00_SYSTEM/schemas/validate.py:82-83`). REAL 샷은 권리 기록 없이도 PASS하므로, 게시 전에 빠질 위험이 있다.
3. **계획의 권리 항목 목록이 스키마 필수 항목보다 적다.** 계획(`SHOOT_PLAN:161`)은 표준 11개 항목만 적었다. 스키마 필수 항목인 `research_permission` · `media_reuse_permission` · `checked_at`이 빠졌다 (`00_SYSTEM/schemas/rights.schema.json:121-134`).
4. **증빙으로 무엇을 남길지 구체적이지 않다.** 규칙 5는 "원본 파일 보관"이라고만 한다. 다음이 하나도 정해지지 않았다.
   - 촬영 날짜
   - 장소 (샷 ID · GPS)
   - 촬영자 이름 (본인인지 동행자인지. 동행자가 찍으면 권리가 누구에게 있는지)
   - 원본 파일 보관 위치와 백업 사본
   - 파일명 규칙
   - 카메라 메타데이터 보존
   
   `08_REAL_FOOTAGE/_README.md:186`은 "파일은 미추적, 경로·rights_id 기록"이라고만 적었다.
5. **자체 녹음(현장음)도 같은 규칙이 필요하다.** 계획에는 영상 클립만 적혀 있다.

### 사용자 결정 필요: 촬영 허가 (규칙을 지어내지 않음)

저장소에는 허가 규칙이 **없다**. 계획도 "현장 확인 필요"로 남겼다 (`SHOOT_PLAN:127-129,166,168-169`). 샷 데이터에도 "촬영 허가 확인"이 있고 (`shot_EP01_S03_SH001.json:34`), 대본도 "if filming is permitted"라고 적었다 (`episodes/ep01-production-script-v2.md:62`).

- 여행 정보 모음 사이트 [ExcursionMania – Cheonmachong](https://www.excursionmania.com/ttd/7916/cheonmachong-tomb-blg-7916) 등의 검색 요약: "Photography is allowed, though some areas may restrict flash" / "some interior tomb areas may restrict cameras". 관리 기관 공식 페이지가 아니므로 **근거로 쓰면 안 된다.**

## 4. 계획과 현재 데이터 사이의 틈·모순
